# 未冻结批次的无效提交登记修复

2026-10-13 用户授权修复并部署：SignOs 的错误完整 SHA 已进入失败批次；普通关联修复会继承不存在的提交，无法完成发布。

## 合同

- `ready` 的服务入口先从项目配置的远端获取精确 SHA，并核对其为 commit；失败、超时、非提交对象不改变 task 状态。网络操作不持有数据库事务，不推进分支。
- `register --repairs-batch LEAF --corrects-task ORIGINAL` 显式创建更正任务。只接受当前作用域最新失败叶批次、尚未冻结、其诊断明确记录 ORIGINAL 的远端 SHA 不存在；其他失败仍走普通关联修复。
- 就绪前再次核对旧 SHA 确实远端不存在，新 SHA 必须已推送；不允许以更正省略有效提交。
- 新批次仅排除被显式更正的无效任务，继承其他任务及恢复链；在 manifest 和 receipt 中记录原 task/SHA 与更正 task/SHA。原任务与失败批次的 SHA、诊断及文件保持不变。
- 子批次全部阶段验证通过后，原任务标记 recovered 并引用同一成功凭证。已冻结批次和已发布标签不可更正。
- 重复请求幂等；并发更正同一原任务最多接受一个，响应丢失和服务重启不得丢失更正关系。

## 执行计划

1. 新增真实 bare Git 远端、Unix socket、工作线程与并发回归；先复现错误登记及修复链失败。
2. 添加远端提交校验、任务更正字段/API/CLI、批次替换与凭证记录；保留锁、冻结和普通恢复合同。
3. 全部回归通过并独立审查，同步 README/USAGE/接入说明与版本。
4. 提交 push，核对远端 CI；沿现有登录启动模式更新不可变运行时，检查版本、socket与状态保留。
5. 以实际远端开发 SHA 建立 SignOs 更正任务，等待 GitHub Release 与固定 OTA 完整验收。
